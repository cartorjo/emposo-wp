# Install-day readiness review — 2026-09-19

A snapshot, not a living document. It records what was true when the port was
declared ready, what was deliberately left undone, and which earlier claims
have since been corrected — so the next person does not have to re-derive any
of it.

## Repository state at the time

`main` and `origin/main` both at `9c973e3`; working tree clean; `main` the only
local branch; all four workflows green at that commit. The three theme edits
install day depends on (noindex gating, the `is_404()` guard, `parts/fallback.php`
rendering content) are on `main`, as is the scaffold slug-conflict fix.

## Visibility, and what it decides

The repository is **private**. It was public for one day (2026-09-18) and then
returned to private, which has three consequences worth writing down because
they are invisible until something fails:

1. **No branch protection.** On a free plan, protection needs a public repo or
   GitHub Pro — the API answers `403: Upgrade to GitHub Pro or make this
   repository public`. Rules applied during the public day are inert. `main` is
   force-pushable, and a red pull request can be merged. Accepted: there is one
   committer.
2. **`.github/CODEOWNERS` is inert.** It does nothing without protection. Kept
   deliberately, because it costs nothing and becomes live again if the
   repository goes public or onto Pro. Not a bug.
3. **No CodeQL job.** Code scanning needs Advanced Security on a private repo,
   so the analysis runs and the upload fails. The job was removed, briefly
   restored during the public day, and removed again. A permanently red check
   teaches people to ignore red checks, and `continue-on-error` on a security
   job reports a success that never happened.

Consequently, commit `faa44bd` ("Simplify CI now that both repositories are
public") is half-true today: `emposo-wp` is private again, and the
simplifications it made still work only because the **submodule** repository
(`cartorjo/weave-clone`) stayed public, so the default `GITHUB_TOKEN` can still
clone `reference/static`. If that ever changes, all three workflows already
print an error naming the `SUBMODULE_TOKEN` secret to add.

Also, while private: metered Actions minutes. Parity and audit therefore skip
Dependabot's pull requests — they boot Docker and drive a browser, which a
dependency bump does not warrant. Code quality and Supply chain still run on
every PR, which is where a lint or advisory regression would appear.

## Corrections to earlier documents

Everything in `docs/install-runbook.md` marked **[corrected]**. The two that
matter most:

- **Lenis is no longer a packaging trap.** `.gitignore`'s unanchored `vendor/`
  used to exclude `themes/emposo/assets/vendor/lenis.min.js`, so a clone had no
  smooth scrolling and every front-end script early-returned. Anchored to
  `/vendor/` and the file is tracked; `git archive HEAD` is now safe.
- **`verify --media` reports rather than enforces alt-text divergence.** It
  walks the export and hard-fails on a missing image, missing alt text or a
  missing file, but only warns when alt text differs from the export — because
  runbook step D4 has to stay runnable once editors improve descriptions.

## Deliberately not done

- **No PHPUnit suite, no `test-php` job.** Risk 10 (`has_archive => false`) is
  asserted by `verify --invariants`. Risk 7 (the `mb_strlen` metric word-class
  boundary) is covered by DOM parity for the ten existing metric values — a
  metric added later has no assertion. Revisit when someone adds one.
- **No Lighthouse in CI.** A shared runner cannot reproduce host LCP. The
  install-day substitute is measuring LCP and TTFB on the host
  (`docs/launch-checklist.md`, section 4).
- **`industries[].cases` is not imported into `_emposo_case_order`.** It looks
  like the missing piece and is a trap: the static build orders those cards by
  its global projects array filtered by industry, not by the cases list — on
  `industrials-manufacturing` the reference renders `rechenzentrums-umzug`
  third while the cases list puts it last. Importing it would silently reorder a
  live page. The comments in `inc/fragments.php` and
  `cli/class-import-command.php` say so at the two places someone would edit.

## Measurement caveat worth knowing

The audit's relative byte and request budgets compare the **post-scroll**
totals, not the initial load. Two lazy images sit exactly at the fold on
`/branchen/`, and whether their fetch starts before `networkidle` is a race —
the same pinned reference measured 20 requests in one run and 22 minutes later.
Bytes are decompressed body lengths, not `Content-Length`, because WordPress
behind Apache gzips and the static reference server does not. The committed
baseline was regenerated with that accounting; the previous one undercounted
requests and used compressed sizes for text, which made WordPress look 23%
heavier than a reference it actually matched to 0.9%.
